Summary

Teams that coordinate work in a shared Excel workbook pay for it every week: statuses drift (“Pending”, “Under Review?”, blank), nobody owns half the rows, everyone can read every row, and there is no history of who changed what.

Kairo replaces that workbook with a secure, AI-assisted task workspace without asking the team to abandon Excel on day one: the existing sheet is imported through a validation preview, and a styled spreadsheet can be exported back at any time.

The solution

Every capability below is implemented in the repository today.

Excel round-trip

Upload .xlsx, review a dry-run preview (legacy statuses mapped, rows missing a title held back), commit. Export back with native dropdowns on status and priority.

Isolated workspaces

Every task query passes one scope filter. Users see only their own, assigned or project tasks; probing anyone else’s task ID returns 404, not 403. Admins see the organisation.

Copilot

Turns a sentence into a structured task with a checklist, breaks work down, explains priority and plans the day, using only your own tasks. Works fully offline.

Chat assistants

A floating assistant creates, edits and closes tasks, comments and projects from plain language. Admins get their own, with organisation-wide reach. Deletes always wait for an explicit yes.

Four ways to work

Dense list with bulk actions, drag-and-drop board, calendar, and a task drawer with checklist, comments and activity log. Ctrl/⌘ K jumps anywhere.

Governance

User provisioning and roles, an organisation-wide audit trail, and productivity insights for admins.

Why this approach

  • Low switching cost. The import and export loop lets the team migrate gradually and keeps stakeholders who still want a spreadsheet.
  • Security by construction. Isolation lives in the data-access layer (get_scoped_tasks_query, get_task_or_404), not in hidden UI, and the assistants act through the same layer. It is covered by automated tests.
  • No lock-in on AI. The Copilot needs no API key; the chat assistants use Groq and can be switched off by leaving the key empty.

Success measures

Proposed targets to agree with the sponsor. These are not measured results.

  • 100% of active work items live in Kairo by the end of the pilot; the shared workbook becomes read-only.
  • Zero cross-user data exposures, verified by the isolation test suite on every change.
  • Every task has an owner and a valid status after import, enforced by the preview.
  • Weekly stakeholder reports come from the Excel export instead of hand-edited sheets.

Risks and mitigations

RiskMitigation
Default secrets reach productionStartup fails on Vercel if JWT_SECRET_KEY is the public default
Messy legacy sheetsDry-run preview; rows missing a title are held back and statuses normalised
AI output qualityThe offline engine is predictable; drafts are always editable and never auto-committed
An assistant deletes the wrong thingDestructive actions need an explicit “yes” from the person, enforced on the server, and every assistant turn is logged
Groq free-tier rate limitsAutomatic fallback to a smaller model, then a short retry; the rest of the app is unaffected
Serverless cold startsOne lightweight function, NullPool against Neon’s pooler, static assets on the CDN
AdoptionExcel export stays available; the landing page and a 20-second tour explain the product

Cost model

Hosting runs on two managed services, each with a free tier suitable for a pilot: Vercel (frontend and Python function) and Neon (PostgreSQL). The chat assistants use Groq, whose free tier is rate-limited per minute. Paid tiers are needed only for production-scale traffic; check each vendor’s current pricing before the expansion step.
